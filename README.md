# DBF Website Maintainer Guide

This repository contains the Washington University in St. Louis Design-Build-Fly team website.

If you are opening this filesystem years from now with no prior context, start here. This document is meant to help you:

- understand what this project is
- find the main content and image files quickly
- preview the site locally
- make common edits safely
- build the static site for deployment

The site is a Next.js app, but most day-to-day changes are made by editing the data files in the `data/` folder rather than changing React component code.

## What This Project Is

This is the public-facing website for WashU Design-Build-Fly. It includes:

- a homepage
- team pages for each subteam
- a join page
- a partner/sponsor page
- a photo dashboard page used to inspect image usage

The site is configured as a static export. In practice, that means:

- you preview locally with `npm run dev`
- you build the deployable site with `npm run build`
- you deploy the generated `out/` folder to your web host

## Quick Start

Install dependencies:

```bash
npm install
```

Start a local preview server:

```bash
npm run dev
```

By default, Next.js will try to use `http://localhost:3000`. If that port is already in use, it may pick another port automatically.

Build the static export:

```bash
npm run build
```

After a successful build, the deployable files will be in:

```text
out/
```

If you need to publish the site to a generic static host, upload the contents of `out/`.

## Project Layout

These are the most important folders and files:

```text
app/                Route entrypoints

data/               Main content/config layer for the site
public/             Static assets such as images, headshots, and favicon
```

Important route files:

## The Main Files You Will Edit

Most content changes should be made in the `data/` folder.

### `data/homeContent.js`

This is the main shared content file for the site. It controls:

- brand text such as the title and metadata
- homepage hero text
- the mission section
- the "Who We Are" section
- past aircraft content
- Meet the Crew labels and blurbs
- social links
- footer links and contact info
- sponsor/join text
- navigation labels

If you want to change homepage text, footer text, navigation labels, recruitment copy, sponsor copy, or shared brand wording, start here.

### `data/teamData.js`

This controls team-page-specific content, including:

- team titles and slugs
- subteam descriptions
- hero images
- about-section copy
- carousel configuration

If you want to change a team page, start here.

For carousel items, each team can define:

- `items`: the slide list
- `maxHeight`: current display cap for the carousel
- `displaySrc` on a slide when you want to show a cropped or presentation-specific version of an image while preserving the original source asset path in `src`

### `data/people.js`

This controls people data shown on the site:

- presidents
- subteam leads
- admin leads

Each person record includes:

- `name`
- `major`
- `gradYear`
- `email`
- `section`
- `image`

If you need to update names, majors, graduation years, emails, or role assignments, edit this file.

### `data/photos.js`

This is the central map of image paths used across the site. It includes:

- homepage images
- legacy aircraft images
- headshots
- team hero/about images

If a page is showing the wrong image, this is one of the first places to check.

## Common Editing Tasks

### Change homepage text or footer/navigation text

Edit:

```text
data/homeContent.js
```

Typical examples:

- mission copy
- about text
- footer contact details
- Instagram and LinkedIn links
- navigation labels
- join-team wording

### Change a team blurb or team page content

Edit:

```text
data/teamData.js
```

Typical examples:

- short subteam descriptions
- large team-page blurbs
- team hero descriptions
- team carousel slides

### Update carousel images

Edit:

```text
data/teamData.js
```

Carousel image files currently live under:

```text
public/images/Carousel/
```

If you add a new image:

1. place the asset in `public/images/Carousel/`
2. reference it in `data/teamData.js`
3. rebuild the site

If the raw image has awkward whitespace or framing, use `displaySrc` for a cleaned-up presentation version while keeping `src` as the original asset reference.

### Update people, majors, emails, or team leads

Edit:

```text
data/people.js
```

Headshots are generally stored under:

```text
public/headshots/
```

Then referenced through `data/photos.js` and used by `data/people.js`.

### Update image paths site-wide

Edit:

```text
data/photos.js
```

This is the central image lookup file. If you move or rename assets in `public/`, update this file so the site points at the correct paths.

### Update favicon or logo assets

Relevant paths:

```text
public/images/favicon.ico
public/images/DBF Logo.png
app/layout.js
data/homeContent.js
```

The favicon is configured in `app/layout.js`. The main site logo path is defined in `data/homeContent.js`.

## Asset Storage Conventions

Static assets live in `public/`. Common locations in this repo:

- `public/images/`: general site images
- `public/images/Carousel/`: team carousel images
- `public/headshots/`: people images
- `public/images/favicon.ico`: favicon

When possible, keep asset names descriptive and stable. Changing filenames is fine, but remember to update any references in `data/photos.js` or `data/teamData.js`.

## Photo Dashboard

There is a built-in photo dashboard at:

```text
/photos
```

This page is useful when you want to:

- see what image paths are currently wired into the site
- visually inspect team and people assets
- copy asset URLs quickly

This page is driven by `data/photos.js` and parts of `data/teamData.js`.

## Deployment

This project is set up for static export. The expected flow is:

1. make your content or code changes
2. run `npm run build`
3. upload the generated `out/` folder to your static host

Important:

- do not deploy `.next/` or `.next-dev/`
- do not edit files inside `out/` manually and treat that as the permanent fix
- always rebuild after source changes

## Known Quirks And Cautions

### Static export is intentional

`next.config.js` uses:

- `output: 'export'`

That means this repo is meant to generate a static site, not run as a permanently hosted Node server.

### Development and production build folders differ

`next.config.js` also uses different output directories for development and production:

- development: `.next-dev`
- production build: `.next`

This is intentional and helps avoid dev/build conflicts.

### `app/layout 2.js` appears to be stale

There is a file named:

```text
app/layout 2.js
```

Do not assume it is active. The canonical root layout is:

```text
app/layout.js
```

If you ever clean up the repo, inspect `app/layout 2.js` first, but do not treat it as the source of truth.

### Some carousel slides may use `displaySrc`

In `data/teamData.js`, a carousel slide may include both:

- `src`
- `displaySrc`

This means the site may intentionally show a cropped or cleaner display version of an image while preserving the original asset reference separately. If a carousel image looks different from the raw source file, check for `displaySrc`.

### The site is content-driven

Much of the visible site content is controlled by `data/*.js`, not hardcoded directly in the page files. Before editing React components, check whether the change is actually a content/config change.

## Suggested Maintenance Workflow

For most updates, this is the safest order:

1. edit content in `data/` or assets in `public/`
2. run `npm run dev` and inspect the affected page
3. run `npm run build`
4. deploy the refreshed `out/` folder

## If You Need To Go Deeper

If you need to change layout, styling, or behavior rather than content:

- check `components/` for reusable UI pieces
- check `app/` for route-level composition
- check `app/globals.css` and component CSS modules for styling

But for ordinary maintenance, start with:

- `data/homeContent.js`
- `data/teamData.js`
- `data/people.js`
- `data/photos.js`

Those four files are the main maintenance surface of this project.
